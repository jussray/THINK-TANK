# Project Sovereignty Contract

THINK-TANK must preserve deterministic reasoning, identity, continuity, and evidence meaning if an external model, provider, API, SDK, connector, runtime, sibling project, or vendor disappears or materially changes.

## Invariants

- **Human authority comes first.** Authorized humans are the root of consequential authority. Models, agents, providers, workflows, evidence, learned knowledge, fingerprints, proof cookies, and automations may inform or constrain a proposal but may not manufacture, renew, widen, or replay authority.
- Human authority does not rewrite reality. Approval can authorize an action; only evidence can support a truthful execution or outcome claim.
- Project-owned contracts define canonical inputs, outputs, errors, authority, state, evidence, and completion semantics.
- External providers and sibling projects are adapters/capabilities, not project identity.
- Critical dependencies are `REPLACEABLE`, `DEGRADED_FALLBACK`, `HARD_DEPENDENCY`, or `UNKNOWN`.
- Provider/model loss may reduce capability but must not erase deterministic V0 behavior, continuity state, evidence meaning, or recovery instructions.
- Provider swaps must not broaden authority, replay stale approvals, duplicate mutations, or weaken evidence requirements.
- Provider outcomes map into project-owned receipts; provider acceptance is not outcome proof.

## Verified deterministic continuity runtime

The current inspected `_site` artifact is a provider-independent continuity build for deterministic V0.

Current CI proves the following path in Chromium:

```text
build inspected _site artifact
  → disable network access
  → open _site/index.html by file://
  → complete founder interview
  → compute deterministic assessment
  → persist IdeaRecordV1 locally

```

This means the deterministic V0 continuity artifact does not require GitHub Pages, Vercel, Supabase, an AI provider, or a local HTTP server to execute in the browser configuration that is actually tested.

The scope is intentionally precise:

- **VERIFIED:** Chromium offline packaged-file execution, deterministic assessment, reload recovery, and portable export.
- **NOT UNIVERSALLY CLAIMED:** identical `file://` persistence semantics in every browser or operating system.
- **NOT INCLUDED:** provider-backed AI, research, authentication, server sync, billing, teams, API access, or public deployment.

The locally served development path remains supported and separately browser-tested. Offline artifact readiness never proves public-runtime identity.

## World as experience and knowledge

Legitimate real-world interaction may become evidence-bearing experience: human reports, deterministic test outcomes, repository history, provider/runtime observations, experiments, documents, operational failures, and verified outcomes.

```text
World → observation → provenance → evidence classification → experience receipt → knowledge candidate → contradiction / red-team check → context + confidence + freshness → working knowledge → proposal → authorized action when applicable → outcome evidence → new experience
```

Experience is not automatically truth. Working knowledge must remain provenance-backed, scoped, challengeable, freshness-aware, and supersedable.

## Think Tank boundary

This repository’s current V0 truth remains deterministic. World-derived knowledge, model output, or future provider-backed capability must not be represented as implemented AI, production runtime, Supabase/auth/billing/API capability, or deployment truth unless separately built and proved. Presence in FCR continuity coverage grants no FCR portfolio, MCP, merge, deployment, provider, or execution authority.

> What experience is being learned from, what would falsify the conclusion, and who actually holds authority for the next consequential action?

Architecture docs are not failover or learning proof. Verify deterministic contract, focused tests, runtime where applicable, authority, data exit, and real-path evidence separately.
